一、上传 / 托管到 GitHub 说明
────────────────────────────────────────────────────────────────
  本许可**允许再分发**（第 Distribution License 条）：任何拿到副本的人
  都可以把源码或修改版继续分享出去，只要随附许可全文与 NOTICE。
  因此把本项目公开托管在 GitHub（公有仓库）**完全符合许可**。

  GitHub 并不要求仓库必须使用 OSI 认证许可；PolyForm Noncommercial
  属于 **source-available（源码可见）** 而非 OSI 开源。
  仓库里建议：
    · 根目录放 `LICENSE` 与 `NOTICE`（本仓库已具备）
    · README 顶部写明「非商业使用免费；商业使用需授权」
    · 仓库 Settings → 不要开启 GitHub Sponsors 之外的商业暗示

二、如何尽可能避免未来的纠纷（已做的与建议做的）
────────────────────────────────────────────────────────────────
  已做：
    ✅ 明确的版权人：`Copyright 2026 秋夕月拾旧`（LICENSE / NOTICE / 源文件 SPDX 头）
    ✅ 明确的 Required Notice 行（分发者必须原样保留，防「抹名」）
    ✅ 免责与责任限制（同 MIT 级别，覆盖交付给学校的场景）
    ✅ 专利授权 + 专利反击条款（第 Patent License / Patent Defense 条）
    ✅ **32 天违约补救期**（第 Violations 条）：
       对方首次违规时，只要在收到通知后 32 天内整改，授权即恢复 ——
       比 AGPL 的「一次违规永久终止」温和得多，真正的纠纷更少
    ✅ 第三方依赖全部宽松许可，无强传染，不存在「被依赖方倒逼开源」的风险
    ✅ 随包分发 LICENSE / NOTICE / THIRD-PARTY-NOTICES

  建议做的：
    · 给「商业授权」留一条明确联系方式（见 NOTICE 第二节），
      并在 README 里重复一次 —— 让潜在商业用户知道有正规途径，
      比事后追责更省事
    · 若将来有外部贡献者提交代码，考虑让其签署一份简单的贡献者声明
      （确认其有权提交、并同意按本许可发布）—— 这一步能避免
      「贡献者事后反悔」这类最常见的开源纠纷
    · 交付给学校时，随附一份简短的《使用说明》，写明：
      「教学用途免费、无需授权；请勿用于对外收费项目」

四、从源码复现本次交付的二进制
────────────────────────────────────────────────────────────────
  1. 安装 Node.js 22+ 与 npm
  2. npm.cmd install            （依赖下载；国内可用 .npmrc 里的镜像）
  3. node scripts/set-version.mjs
  4. node scripts/build-setup.mjs
  5. node scripts/build-installers.mjs
     → 产出 dist-installer/ 下的两个安装包

  详细步骤与验证方式见仓库根目录的《交接说明》。
